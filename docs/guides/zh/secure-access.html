安全访问

使用静态请求头令牌或签名短时 URL，对发往沙箱端点的入站 HTTP 与 WebSocket 流量进行鉴权。

安全访问（Secure Access）是 OpenSandbox 针对沙箱端点的入站访问控制。在沙箱上启用后，入口网关（以及服务器代理路径）要求每个调用方在 HTTP 或 WebSocket 流量到达沙箱之前证明自己已获授权。

相关能力：

  • 凭证保管库 — 保护出站请求。
  • 安全容器运行时 — 隔离工作负载。

要求

  • Kubernetes 运行时（Docker 会以 400 拒绝 secureAccess: true）。
  • [ingress] mode = "gateway"。
  • 签名 URL 还需要配置 [ingress.secure_access]，且至少有一把签名密钥。

工作原理

在控制面，以 secureAccess: true 创建沙箱并调用 GetEndpoint，会得到每个沙箱一份不透明的 SecureAccessToken。若再传入 ?expires=<unix_seconds>，还会用 [ingress.secure_access] 下的当前密钥签发有时效的路由令牌。

在数据面，入口网关按固定顺序评估两种机制：

  1. 存在请求头 → 与 SecureAccessToken 做常量时间比较。不匹配立即返回 401；不会回退到签名 URL 分支。
  2. 没有请求头 → 解析签名令牌，检查 now ≤ expires，并校验签名。

通过任一检查的请求会在转发上游前剥离请求头或签名前缀，因此工作负载永远看不到凭据。

静态请求头令牌

GetEndpoint 返回不透明的 SecureAccessToken。客户端按如下方式附带：

OpenSandbox-Secure-Access: <token>

SDK 会从端点响应中自动带上该请求头，应用代码通常无需手动处理。

签名短时 URL

通过添加 ?expires=<unix_seconds>（十进制 uint64 纪元秒，不是毫秒）来签发签名 URL：

GET /sandboxes/{sandboxId}/endpoints/{port}?expires=<unix_seconds>

返回的路由令牌形如：

{sandbox_id}-{port}-{expires_b36}-{signature}

其中 expires_b36 为 base-36 秒数，signature 为 8 位十六进制加上用于签名的 1 字符 key_id。网关在三种路由模式下均可接受：

模式令牌出现位置
wildcardHost：{token}.<parent>
header沙箱路由请求头的值
uri路径前缀：/{sandbox_id}/{port}/{expires_b36}/{signature}/…

使用签名 URL 可以下发可分享、有时效的端点，而无需暴露静态令牌。

服务器配置

签名 URL 需要签名密钥；静态请求头令牌则不需要。

# ~/.sandbox.toml
[ingress]
mode = "gateway"

[ingress.gateway]
# Wildcard mode requires a wildcard address (e.g. *.sandbox.example.com);
# header and uri modes take a plain host (e.g. sandbox.example.com).
address = "*.sandbox.example.com"

[ingress.gateway.route]
mode = "wildcard"   # or "header" or "uri"

[ingress.secure_access]
active_key = "a"    # 1 char [0-9a-z], must exist in keys

[[ingress.secure_access.keys]]
key_id = "a"
key = "<base64-encoded-secret>"   # raw base64, no "base64:" prefix

opensandbox-server Helm chart 在 server.gateway.secureAccess 下暴露相同结构，并将密钥同时注入服务器与入口网关。

为避免把密钥材料写进配置文件，服务器也接受环境变量 OPENSANDBOX_SECURE_ACCESS_KEYS（a=<base64-secret>[,b=...]）与 OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY（a），它们会覆盖 TOML 配置块；chart 的 server.gateway.secureAccess.existingSecret 选项可从 Secret 注入这些变量。

密钥轮换。新增密钥条目并部署，再切换 active_key。校验会加载所有已配置密钥，因此旧密钥签发的令牌在你删除它们之前仍有效——请保留旧条目，直到最长可能的令牌有效期结束。

启用

创建时设置 secureAccess: true。各 SDK 对应写法：Python secure_access=True，JS/TS secureAccess: true，C# SecureAccess = true。

curl -X POST http://localhost:8080/v1/sandboxes \
  -H "Content-Type: application/json" \
  -d '{
    "image": {"uri": "python:3.11"},
    "resourceLimits": {"cpu": "500m", "memory": "512Mi"},
    "entrypoint": ["python", "/app/main.py"],
    "secureAccess": true
  }'

调用受保护端点

使用静态请求头令牌：

# Fetch endpoint; the response carries OpenSandbox-Secure-Access.
curl -s http://localhost:8080/v1/sandboxes/${SANDBOX_ID}/endpoints/8080

curl -H "OpenSandbox-Secure-Access: ${TOKEN}" \
  https://${SANDBOX_ID}-8080.sandbox.example.com/

使用签名 URL（有效期一小时）：

EXPIRES=$(( $(date +%s) + 3600 ))
curl -s "http://localhost:8080/v1/sandboxes/${SANDBOX_ID}/endpoints/8080?expires=${EXPIRES}"
# → https://{sandbox_id}-8080-{expires_b36}-{signature}.sandbox.example.com/

错误

状态码原因
400 在 Docker 上设置 secureAccess: true；畸形的 expires 或路由令牌；无效的 expires_b36 / port / signature。
401 请求头不匹配；签名 URL 已过期；签名错误；未知的密钥 ID；需要安全访问但未提供凭据。

在 GetEndpoint 上省略 expires 并不是 400——它会返回未签名的响应，其中仍携带静态 SecureAccessToken。

说明

  • 强制执行覆盖入口网关与服务器代理路径（/v1/sandboxes/{id}/proxy/...），包括 HTTP 与 WebSocket。
  • 网关在转发前会剥离 OpenSandbox-Secure-Access 以及任何签名 URI 前缀。
  • 在 URI 模式下，仅当沙箱确实启用了安全访问时，形如 expires_b36/signature 的路径段才会被解释为签名前缀；否则完整路径会原样转发。
  • 安全访问与 execd 访问令牌（X-EXECD-ACCESS-TOKEN）以及凭证保管库相互独立；三者可一并使用。
