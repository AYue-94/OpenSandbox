Windows 沙箱

通过 KVM/QEMU 在 Linux 容器中运行 Windows 客户机，并由 OpenSandbox 生命周期 API 管理。

Windows 沙箱通过 KVM/QEMU 在 Linux 容器中运行 Windows 客户机，并由 OpenSandbox 生命周期 API（创建、暴露端点、删除）端到端管理。当前 Windows 配置文件基于 dockur/windows，由 OpenSandbox 提供服务集成与能力。

范围

本指南覆盖 OpenSandbox Server 的 Windows 配置文件（platform.os=windows）：

  • 创建 Windows 沙箱
  • 查看状态与端点
  • 常见资源与卷设置
  • 删除与清理

工作原理

  • 运行时：dockur/windows 在 Linux 容器中运行 Windows 客户机（需要 KVM/QEMU），使用 /storage、/boot.iso 等挂载点存放系统盘与安装介质。
  • 控制面：创建时，OpenSandbox Server 注入 Windows 配置文件（设备、capabilities、execd、端口映射），并执行资源检查、状态管理与端点发布。
  • 客户端：通过生命周期 API 或 Python SDK，指定 platform.os=windows，然后按 创建 → 轮询 Running → 获取端点 → 使用 → 删除 的流程操作。

前置条件

  • 可访问的 OpenSandbox Server（例如 http://localhost:8080）
  • 主机满足 Windows 配置文件要求：
    • 存在 /dev/kvm
    • 存在 /dev/net/tun
  • 服务器已配置 storage.allowed_host_paths，以允许主机路径
  • 建议准备一个绑定到 /storage 的主机目录
  • 可选：本地 Windows ISO 用于 /boot.iso（可减少重复下载时间）

关键设置与约束

平台与镜像

  • 设置 platform: {"os":"windows","arch":"amd64"}（arm64 取决于主机）
  • 建议镜像：dockurr/windows:latest；参见 dockur/windows releases 与 Docker Hub tags

最低资源

Windows 配置文件强制要求：

  • resourceLimits.cpu >= 2
  • resourceLimits.memory >= 4G
  • resourceLimits.disk >= 64G

resourceLimits 与环境变量

若设置了 resourceLimits，服务器会将其映射并覆盖下列环境变量：

  • CPU_CORES
  • RAM_SIZE
  • DISK_SIZE

请只使用 resourceLimits；不要手动设置这三个环境变量。

默认端口与 USER_PORTS

Windows 配置文件默认接通这些端口：

  • 44772（execd）
  • 8080
  • 3389/tcp、3389/udp（RDP）
  • 8006/tcp（典型 Web 控制台）

同时会构建或合并 USER_PORTS（通常为 44772,8080,3389,8006）。

存储挂载

  • 将可写主机目录绑定到 /storage
  • 可选：将 ISO 文件以 readOnly=true 绑定到 /boot.iso
  • 主机路径必须落在 storage.allowed_host_paths 之下，否则请求会被拒绝

端到端示例（Python）

该流程：

  1. 创建 Windows 沙箱
  2. 等待进入 Running
  3. 获取 44772 端点
  4. 用 Python SDK 操作沙箱
  5. 删除沙箱

最小示例

import os
from datetime import timedelta

from opensandbox import SandboxSync
from opensandbox.config import ConnectionConfigSync
from opensandbox.models.sandboxes import PlatformSpec

BASE_URL = os.getenv("OPEN_SANDBOX_BASE_URL", "http://localhost:8080")
API_KEY = os.getenv("OPEN_SANDBOX_API_KEY", "")


def main() -> None:
    cfg = ConnectionConfigSync(
        domain=BASE_URL,
        api_key=API_KEY or None,
        use_server_proxy=True,
    )

    sbx = None
    try:
        sbx = SandboxSync.create(
            image="dockurr/windows:latest",
            timeout=timedelta(hours=12),
            ready_timeout=timedelta(minutes=30),
            resource={
                "cpu": "4",
                "memory": "8G",
                "disk": "64G",
            },
            env={"VERSION": "11"},
            entrypoint=["cmd", "/c", "echo OpenSandbox Windows profile"],
            platform=PlatformSpec(os="windows", arch="amd64"),
            connection_config=cfg,
        )
        print("created:", sbx.id)

        endpoint = sbx.get_endpoint(44772)
        print("execd endpoint:", endpoint.endpoint)
        print("sdk health:", sbx.is_healthy())
    finally:
        if sbx is not None:
            try:
                sbx.kill()
                print("deleted:", sbx.id)
            finally:
                sbx.close()


if __name__ == "__main__":
    main()

示例会等待 SDK 健康检查（ready_timeout=30m）。Windows 冷启动可能较慢；请按需增大 ready_timeout。若需自定义就绪逻辑，可使用 skip_health_check=True，并在应用中自行轮询 Running。

进阶选项

持久化 /storage

将主机路径绑定到 /storage，作为持久的系统/用户数据目录。该目录不必事先存在：绑定挂载时可能会新建（全新），若已存在则会复用。host.path 无论目录是否存在，都必须位于允许的 storage.allowed_host_paths 前缀下。

from opensandbox.models.sandboxes import Host, Volume

volumes = [
    Volume(
        name="win-storage",
        host=Host(path="/data/opensandbox/windows-storage"),
        mount_path="/storage",
        read_only=False,
    ),
]
# Pass as SandboxSync.create(..., volumes=volumes, ...)

主机上已有 ISO

将本地 Windows 安装 ISO 以只读方式绑定到 /boot.iso，可避免每次下载介质（同样需要 allowed_host_paths；路径必须是文件）：

from opensandbox.models.sandboxes import Host, Volume

volumes = [
    Volume(
        name="win-iso",
        host=Host(path="/data/iso/Win11_23H2.iso"),
        mount_path="/boot.iso",
        read_only=True,
    ),
]

自定义 dockur/windows

dockur/windows 通过环境变量配置。OpenSandbox 会按上游文档将你的 env 传入容器。安装 / UX 相关设置常见包括：

  • VERSION：Windows 变体代码（例如 11、11l、10——完整表见项目 README），某些情况下也可以是自定义 ISO 的 https:// URL
  • USERNAME / PASSWORD：首个用户与密码（省略时使用镜像默认值——见上游）
  • LANGUAGE：安装语言（例如 English、Chinese）
  • REGION / KEYBOARD：区域与键盘布局（例如 en-US、zh-CN）
  • 进阶场景可能用到 DHCP、ARGUMENTS（额外 QEMU 参数）等——见 dockur/windows FAQ

若已通过 resourceLimits 设置 CPU、内存与磁盘，请不要再在 env 中重复 dockur 文档里的同类资源键；参见上文 resourceLimits 与环境变量。其他非资源键可自由组合。

env = {
    "VERSION": "11l",
    "USERNAME": "Docker",
    "PASSWORD": "your-secure-password",
    "LANGUAGE": "Chinese",
    "REGION": "zh-CN",
    "KEYBOARD": "zh-CN",
}

完整列表、默认值与交互说明，请参阅 dockur/windows 仓库 与镜像标签。

使用自有 Windows 镜像

在 dockur/windows 文档中，“your own” 通常指使用哪一份 Windows 安装 ISO——而不是与上游无关的自定义配方。自定义安装 FAQ 写明：

  • 对于项目版本表中没有的 ISO，将 VERSION 设为该 ISO 的下载 URL（https://...）；容器会拉取并安装。
  • 若你已有本地 ISO 文件，按上文 主机上已有 ISO 将其绑定到 /boot.iso；上游文档说明此时会忽略 VERSION。

在 OpenSandbox 中，在 env 里设置 VERSION，需要时再为本地 ISO 添加挂载到 /boot.iso 的卷，与上游流程一致；image 保持为 dockurr/windows 或其他兼容上游镜像，与其他示例相同。

VERSION = ISO URL 场景片段（与最小示例传入 env 的方式相同）：

env = {
    "VERSION": "https://example.com/path/to/your.iso",
    # same pattern as the minimal example for resource / platform / etc.
}

常见问题

  • 创建时报 Unsupported platform.os 'windows' — 服务器构建未包含 Windows 配置文件；请升级到包含该能力的版本。
  • resourceLimits.* 出现 INVALID_PARAMETER — 确保 cpu >= 2、memory >= 4G、disk >= 64G。
  • 长时间停留在 Pending — 首次 Windows 安装较慢；检查主机资源与 /storage 空间，并增大等待超时。
  • 状态为 Running 但端点不可达 — 确认 GET /v1/sandboxes/{id}/endpoints/44772 返回有效地址；若需转发更多端口，请设置 env.USER_PORTS。
