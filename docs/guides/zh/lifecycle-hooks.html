生命周期钩子

在沙箱入口点启动前执行准备工作，并在运行期间调度周期性任务。

生命周期钩子允许沙箱在运行时的既定时机以声明式方式执行命令。OpenSandbox 当前支持一个阻塞式 preStart 钩子，以及一个或多个非阻塞的 periodic 钩子。

支持的钩子

钩子 数量 运行时机 失败行为
preStart 零或一个 execd 开始监听之后、用户入口点启动之前 失败或超时会阻止用户入口点启动
periodic 零或多个 preStart 成功后启动调度器，并按各自计划运行每个钩子 失败或超时的运行会被记录，后续运行通常仍会继续；若超时进程无法终止，该钩子会被禁用

两类钩子都在沙箱内部、使用沙箱环境运行。命令以参数数组形式直接执行。若需使用管道、重定向或变量展开等 shell 语法，请显式调用 shell，例如 ['sh', '-c', 'command > file']。

两种启动模式下的顺序相同：

  1. execd 启动，其 HTTP 服务器开始监听。
  2. 若已配置，则 preStart 运行至完成。
  3. 若已配置，则启动周期性调度器。
  4. 启动用户入口点。

在 execd-as-init 模式下，execd 保持为 PID 1，并将入口点作为其受监管的子进程启动。在 bootstrap 模式下，bootstrap 进程在 execd 报告生命周期启动完成后启动入口点。

配置

生命周期钩子是沙箱创建请求的一部分：

{
  "image": { "uri": "ubuntu:24.04" },
  "entrypoint": ["tail", "-f", "/dev/null"],
  "resourceLimits": {
    "cpu": "1",
    "memory": "1Gi"
  },
  "lifecycle": {
    "preStart": {
      "command": ["sh", "-c", "echo ready > /tmp/prestart.done"],
      "timeoutSeconds": 120
    },
    "periodic": [
      {
        "name": "checkpoint",
        "schedule": "@every 5m",
        "command": ["sh", "-c", "date -u >> /tmp/checkpoints.log"],
        "timeoutSeconds": 120
      }
    ]
  }
}

preStart

字段 必填 说明
command 是 非空的命令与参数数组
timeoutSeconds 否 省略时默认为 60 秒；显式取值须在 1 到 10800 秒（3 小时）之间

preStart 在每次容器启动时都会运行。请使命令幂等，以免重试或重启沙箱时破坏状态。

periodic

字段 必填 说明
name 是 非空白名称，在同一沙箱内唯一
schedule 是 标准五字段 cron 表达式，或诸如 @hourly、@every 30s 的描述符
command 是 非空的命令与参数数组
timeoutSeconds 否 省略时默认为 60 秒；显式取值须在 1 到 300 秒之间

@every 间隔必须是整数秒，且至少为一秒。同一命名钩子的运行不会重叠：若上一次运行仍在进行，则跳过下一次计划运行。

当前可用性

生命周期钩子目前需要 Kubernetes provider。Docker provider 与 Fast Sandbox 后端会拒绝该配置。请求不能同时使用 lifecycle 与 poolRef。

各 SDK 在沙箱创建 API 上暴露了生命周期字段，但不强制校验超时范围。Server 是请求校验的权威。语言相关示例见 SDK 文档。

运维建议

  • 保持 preStart 有界且确定，因为入口点会等待它完成。
  • 使周期性工作幂等且可安全重试。
  • 通过平台支持的密钥机制存储凭证，而不要嵌入命令中。
  • 将必须在节点替换后仍保留的数据写入持久存储。生命周期钩子用于调度恢复与同步工作；它们本身不会使沙箱文件系统持久化。
